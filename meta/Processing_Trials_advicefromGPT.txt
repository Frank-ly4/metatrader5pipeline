In quant terms you’d do a **broad random (or quasi-random) exploration**, then use a **latent/low-dimensional map** of the trial results to spot **stable basins of performance**, then **zoom/exploit** those basins and confirm with out-of-sample tests.

Below is a concrete, battle-tested way to do it with your parameter set.

---

# A. The “random → latent map → zoom” pipeline

## 1) Sample the space (coverage-first)

* Use **Random**, **Latin Hypercube**, or **Sobol** (low-discrepancy) sampling instead of grid for the first pass.
* Budget: for \~10–14 parameters like yours, start with **500–2,000 trials** (more if you can).
* Apply **hard viability filters** during sampling to save time:

  * min trades ≥ e.g. **50–100**
  * max drawdown ≤ e.g. **25–35%**
  * exposure ≤ e.g. **80–90%**
  * slippage/fees on

## 2) Engineer features for the map

From each trial, build a feature vector combining **parameters** and a few **derived relationships**:

* Raw params: `fast_min_len, fast_max_len, slow_min_len, slow_max_len, dma_atr_len, atr_len, upper/lower_inner_mult, upper/lower_outer_mult, momentum_len, momentum_threshold`.
* Derived (very helpful):

  * `fast_len_mid = (fast_min_len + fast_max_len)/2`
  * `slow_len_mid = (slow_min_len + slow_max_len)/2`
  * `gap_slow_fast = slow_len_mid - fast_len_mid`
  * `gap_inner_outer_upper = upper_outer_mult - upper_inner_mult`
  * `gap_inner_outer_lower = lower_outer_mult - lower_inner_mult`
  * `asym_inner = upper_inner_mult - lower_inner_mult`
  * `asym_outer = upper_outer_mult - lower_outer_mult`
* Normalize (z-score) or min–max these features.

## 3) Choose objective(s)

Use **multiple** metrics and keep the **Pareto set**:

* Primary: **CAR/MDD** or **Return / MaxDD**, **Profit Factor**, **Sharpe/Sortino**, **Expectancy**.
* Guardrails: **min trades**, **stability** (see step 6), **tail risk**.

## 4) Make the latent map

* Dimensionality reduction: **UMAP** (great default), **t-SNE** (slower), or **PCA** (linear baseline).
* Input = normalized feature vector from step 2 (parameters only, not the results).
* Color points by your chosen metric (e.g., CAR/MDD). You’ll see **hot regions**.

## 5) Cluster the map

* Clustering: **HDBSCAN** (handles variable density), **DBSCAN**, or **k-means** (if the geometry is simple).
* For each cluster, compute **median** and **IQR** of key metrics, plus **% of trials** that pass your guardrails.

## 6) Pick **stable winners**, not just peak points

* Define **local stability**: for each trial, compute the metric of its **k nearest neighbors** in param-space; measure the **median drop-off** from the trial’s score to its neighbors.
* Prefer clusters (and points) with **low drop-off**: they’re less likely to be curve-fit spikes.
* Also prefer clusters with **more trades** and **lower variance** across kNN.

## 7) Exploit (zoom) the basins

* Around the best **cluster center(s)**, run a **local fine search**:

  * Either a **fine grid** over narrowed ranges, or
  * **Bayesian/TPE** constrained to that region, or
  * A short **evolutionary** local search (CMA-ES / differential evolution) within bounds.
* Re-check stability and guardrails.

## 8) Validate with time-series aware OOS

* Use **walk-forward** or **purged CV with embargo** (to prevent leakage across splits).
* Compute **PBO** (probability of backtest overfitting) or simply rerun the top configs on **multiple non-overlapping OOS windows**.
* Pick **the cluster median** (or a robust point within 1–2% of the best) rather than the single numerically best.

---

# B. Grid vs Random (your specific questions)

* **Grid**: tries every discrete combination implied by your ranges/steps. If your tool shows “trials”, it usually **caps** after N combinations, not “smartly” selecting them. So yes—if you set 50 trials and choose “grid”, it will typically test **50 systematic combos** in its internal order (but only from the full grid; it won’t cover the whole space unless 50 ≥ total combos).
* **Random**: draws **N random combinations** from the ranges (50 random draws → 50 random combos). With Sobol/Latin Hypercube you get better coverage than pure RNG for the same N.

**Heuristic**:

* Start with **Random/Sobol 500–2,000**.
* Map/cluster → zoom.
* Then a **small focused grid** (hundreds, not millions) inside the best basin(s).

# 2) Backtest orchestration (MT5 Strategy Tester + logging)

You’ll run each parameter vector through MT5 Strategy Tester and **persist a single row per trial** with parameters + results.

**Execution**

* Use MT5 Strategy Tester **agents** (local + network) to parallelize.
* Testing mode: **Every tick based on real ticks** (or at least “Every tick”), fixed spread or variable: match live venue.
* **Slippage & commission**: use realistic/slightly pessimistic values.
* **No Visual mode**.
* **Deposit / leverage** fixed across runs.

**Optimization mode**

* For exploration runs you are not using MT5 “grid/genetic”; you are **feeding explicit parameter sets** (random/Sobol draws).
* Two ways:

  1. *External driver* (recommended): A Python harness sets inputs and calls the tester per run (e.g., via MetaTrader5 Python API, or by generating `.set` files and invoking terminal).
  2. *Inside MT5*: less friendly for random; MT5 offers **Complete enumeration** (grid) and **Genetic** (GA), but not pure random. You can still use **Genetic** for exploration, but coverage is opaque.

**MQL5: return a custom score + log everything**

* Use `double OnTester()` to return a single objective (e.g., CAR/MaxDD with penalties).
* Use `OnTesterPass()` (called after each pass during optimization) to **write a CSV row** with:

  * Parameters used (read from your `input ...` variables)
  * Core stats: NetProfit, MaxDD, PF, Trades, Expectancy, Sharpe/Sortino, Exposure, AvgTrade, HitRate, Long/Short breakdown, etc.
  * Your **composite score** (same as `OnTester()`).

**MQL5 skeleton:**

```cpp
input int    fast_min_len = 12;
input int    fast_max_len = 22;
// ... all inputs ...

double Score=0;

double OnTester()  // MT5 uses this return as "Custom max" criterion if selected
{
   const double net   = TesterStatistics(STAT_PROFIT);
   const double ddAbs = TesterStatistics(STAT_BALANCE_DD);
   const double ddPct = TesterStatistics(STAT_BALANCE_DDREL_PERCENT);
   const double pf    = TesterStatistics(STAT_PROFIT_FACTOR);
   const double trades= TesterStatistics(STAT_TRADES);
   // Composite (example): (Return/MaxDD) * min(PF, cap) * viability
   if(trades < 60 || ddPct > 35.0 || pf < 1.1) return -1e9; // hard reject
   double ret_dd = (ddAbs>0 ? net/ddAbs : 0);
   Score = ret_dd * MathMin(pf, 3.0);
   return Score;
}

void OnTesterPass()
{
   // Called after each optimization pass; write a CSV row
   int h = FileOpen("EA_GoldBands_trials.csv",
                    FILE_WRITE|FILE_READ|FILE_CSV|FILE_SHARE_WRITE|FILE_COMMON);
   if(h != INVALID_HANDLE)
   {
      FileSeek(h, 0, SEEK_END);
      FileWrite(h,
        fast_min_len, fast_max_len, // ... all params ...,
        TesterStatistics(STAT_PROFIT),
        TesterStatistics(STAT_BALANCE_DD),
        TesterStatistics(STAT_BALANCE_DDREL_PERCENT),
        TesterStatistics(STAT_PROFIT_FACTOR),
        TesterStatistics(STAT_TRADES),
        Score);
      FileClose(h);
   }
}
```

# 5) Clustering & stability

**Clustering.**

* **HDBSCAN**: robust to uneven densities; automatically finds cluster count.
* **DBSCAN**: workable if density is uniform-ish.
* **k-means**: only if the geometry looks convex-ish.

**For each cluster:**

* Compute **median** and **IQR** of: Score, MaxDD, PF, Trades.
* Compute **pass-rate** against guardrails (e.g., % with trades≥60 & MaxDD≤35% & PF ≥ 1.2).

**Local stability (kNN drop-off).**
For each trial i:

* Find k nearest neighbors in *parameter space* (use scaled Xn).
* Let `s_i` be the score of i; `S_k(i)` be the median neighbor score.
* Define **stability margin**: `Δ_i = s_i - median(S_k(i))`.
* Prefer points/clusters with **small |Δ|**, i.e., the point is **not** a spike above a bad neighborhood.

```python
from sklearn.neighbors import NearestNeighbors
nbrs = NearestNeighbors(n_neighbors=10).fit(Xn)
_, idx = nbrs.kneighbors(Xn)
local_drop = np.array([scores[i] - np.median(scores[idx[i]]) for i in range(len(Xn))])
```

**Pick clusters** that combine:

* high median score,
* high pass-rate,
* **low median |local\_drop|**.

# 6) Exploit (zoom) within the winning basins

Now restrict to small **bounding boxes** around the best clusters and **search locally**:

* **Fine grid** (hundreds, not millions): integer lengths step 1–2; multipliers step 0.05–0.1.
* Or **Bayesian/TPE** (e.g., scikit-optimize) constrained to the cluster AABB.
* Or small **CMA-ES** inside bounds.

This is where you recover the last few % of performance without curve-fitting.

# 7) Robustness: perturbations & Monte Carlo

Before you anoint a configuration, attack it:

**Data perturbations (re-backtests):**

* **Slippage/fees**: ±(1–3)× your baseline.
* **Spread regime**: widen by p-quantiles seen in live.
* **Time shift**: roll your in-sample window by days/weeks (keep length constant).
* **Tick noise**: inject microstructure noise if your mode isn’t “real ticks”.

**Trade-path Monte Carlo:**

* **Bootstrapped trades** (block bootstrap if serial dependence matters): re-sample trade P\&L sequences; recompute PF, MaxDD, return.
* **Sign/permutation tests** on trade sequence to see tail sensitivity.
* **Parameter jitter**: ±1 around length values; ±0.05 around multipliers → re-run; check metric dispersion.

**Accept only** configs whose metrics don’t collapse under these perturbations. Keep the **median within X%** of baseline and **tails bounded**.

# 8) Time-series validation: Walk-Forward / Purged CV

**Walk-Forward Optimization (WFO)**

* MT5 provides **Forward optimization**: split the history into **train → forward** windows (e.g., 6m train, 3m forward) and step them (rolling).
* Use your exploration method inside each train window (local zoom or small GA), then **lock params** and evaluate on the forward slice.
* Aggregate forward metrics across steps (median PF, median CAR/MDD, worst MaxDD). You want **consistency across steps**.

**Purged K-Fold with Embargo (outside MT5)**

* Split by time (no overlap), **purge** observations near split boundaries, **embargo** a period after each fold to avoid leakage (labeling/trade overlap).
* Compute **deflated Sharpe** or **PBO** (prob. of backtest overfitting) across folds.
* Select **cluster centers** that exhibit high out-of-fold median and low variance.

# 12) Answers to your earlier “grid vs random” nuances in MT5

* **“Complete” optimization (grid):** enumerates the discrete lattice implied by inputs’ ranges/steps. It will try **all combinations** (huge) unless you cap.
* **“Genetic”:** a GA—**not** purely random; it stochastically explores and exploits; coverage is uneven and guided by fitness.
* **Pure random in MT5:** not a built-in mode. To do true random, run **explicit trials** (external driver) or pre-generate a list of random `.set` files.
